# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Run the app
python main.py

# Run all tests (PyQt6 not required — conftest.py stubs it)
pytest tests/

# Run a single test
pytest tests/test_keyword_router.py::test_exact_keyword_triggers_video

# Training pipeline (run from project root in order)
python -m training.record_phrase --phrase "I have a headache for a week now" --samples 30
python -m training.train
python -m training.eval
```

## Hard constraints

- **Zero cloud at runtime.** No requests, no sockets, no external APIs. Every model, voice engine, and dependency must run locally. Don't add any network-dependent library without explicit approval.
- **PyQt6 GUI thread safety.** Worker threads must never call Qt methods directly. All cross-thread communication goes through `pyqtSignal` or `queue.Queue`. Violating this causes silent crashes on some platforms.

## Threading model

This is the most important architectural concept. There are four `QThread` workers; each communicates via signals or queues, never shared state:

```
CameraWorker  ──frame_ready──►  MainWindow.on_frame  (GUI paints preview)
              ──landmarks_ready──►  RecognizerWorker.push_landmarks (queue)

RecognizerWorker  ──recognized(str, float)──►  MainWindow.on_recognized
                                           ──►  TTSWorker.speak (queue)

STTWorker  ──partial_transcript──►  MainWindow.on_partial_transcript
           ──final_transcript──►    KeywordRouter.match (QObject, GUI thread)

KeywordRouter  ──play_video(str)──►  MainWindow.on_play_video
```

`main.py` is the only place where signals are wired together. If you add a new inter-thread connection, add it there.

## Recognition pipeline (Phase 1)

1. `CameraWorker` runs `VisionProcessor.process()` on every frame → emits a landmarks dict `{"hands": [...], "blendshapes": [...], "face_landmarks": [...]}`
2. `RecognizerWorker` calls `features.build_frame_vector()` on each dict to produce a 178-float vector: `[hand_0(63), hand_1(63), blendshapes(52)]`
3. Vectors accumulate in a rolling deque of length `WINDOW_LENGTH=60` (2 seconds at 30 fps)
4. Every `WINDOW_STRIDE=10` frames, `ASLClassifier.predict()` runs on the full window → `(label, confidence)`
5. Dwell+cooldown debounce: the label must appear `DWELL_FRAMES=3` consecutive times above `CONFIDENCE_THRESHOLD=0.60` before `recognized` fires. Then `COOLDOWN_FRAMES=45` frames must pass before it can fire again.
6. Brief hand-loss (< 10 consecutive empty frames) does **not** reset the dwell counter — only a sustained absence does.

## Feature vector layout

`core/features.py` is pure functions with no side effects — always unit-test changes there.

- Landmark normalization: translate so wrist (index 0) is origin, then divide by `max(abs)` → scale-invariant, position-invariant
- If only one hand is detected, `hand_1` is zero-padded
- If face landmarker misses, blendshapes are zero-padded

## Config is the single source of truth

`config.py` owns every tunable constant: thresholds, paths, model hyperparams, `KEYWORD_MAP`, `INITIAL_PHRASES`. Nothing is hardcoded elsewhere. When adding a new phrase or keyword, edit only `config.py`.

## Stylesheet token substitution

`assets/styles.qss` uses `@TOKEN@` placeholders (e.g. `@ACCENT@`, `@BG_PRIMARY@`). `gui/main_window.py:_load_stylesheet()` replaces them at startup from `gui/theme.py` constants. Never put hex colors directly in the QSS file.

## Gitignored assets (not in repo)

These must be present for the app to run but are not committed:

| Path | What it is |
|---|---|
| `assets/mediapipe/hand_landmarker.task` | MediaPipe hand model (~23 MB) |
| `assets/mediapipe/face_landmarker.task` | MediaPipe face model (~33 MB) |
| `assets/vosk/vosk-model-small-en-us-0.15/` | Vosk STT model (~50 MB) |
| `data/recordings/` | Recorded `.npy` training sequences |
| `models/asl_classifier.pt` | TorchScript model, generated by `training/train.py` |
| `assets/asl_videos/*.mp4` | Pre-recorded ASL response clips |

The app degrades gracefully when any of these are absent (prints a warning, disables the affected subsystem).

## Known path issue

The Vosk model zip extracts with a double-nested folder. Config expects `assets/vosk/vosk-model-small-en-us-0.15/am/final.mdl`; if unzipped naively you get an extra level. Move the inner folder up if STT doesn't start.

## Test architecture

`tests/conftest.py` inserts a fake `PyQt6` package into `sys.modules` before any test runs, so all queue-logic and signal-logic tests work without Qt installed. Tests use `SomeClass.__new__(SomeClass)` to bypass `__init__` (which would require real Qt objects) and wire up minimal stubs manually. Keep this pattern when adding new worker tests.
