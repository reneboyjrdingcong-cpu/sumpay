SLIDE 7 — METHODS: PHASE 1 — PATIENT SIDE
Template section: METHODS TO BE USED IN THIS RESEARCH
----------------------------------------------------------------
Headline:
  Phase 1: The Patient Signs — The System Speaks

Three-step visual flow:

  STEP 1 — CAPTURE
  MediaPipe detects up to 2 hands (21 landmarks each) and
  52 facial expression scores per frame.
  → 178-dimensional feature vector, every frame

  STEP 2 — CLASSIFY
  A rolling 2-second window (60 frames) is fed into a
  lightweight Transformer encoder.
  → Predicts signed phrase with confidence score

  STEP 3 — CONFIRM & SPEAK
  Patient reviews the recognized text, confirms, then
  pyttsx3 speaks it aloud to the clinician.
  → No accidental speech. Patient is always in control.

Key spec callout box:
  4 attention heads  |  3 encoder layers  |  ~358K parameters
  Runs on CPU  |  No GPU required

SLIDE 8 — METHODS: PHASE 2 — CLINICIAN SIDE
Template section: METHODS TO BE USED IN THIS RESEARCH
----------------------------------------------------------------
Headline:
  Phase 2: The Doctor Speaks — The Patient Sees

Two-step visual flow:

  STEP 1 — TRANSCRIBE
  Doctor speaks naturally. Vosk (offline Kaldi ASR, ~50 MB)
  transcribes speech in real time at 16 kHz. Live transcript
  appears on screen as they speak.

  STEP 2 — ROUTE TO SIGN
  A keyword router scans the transcript using whole-word
  pattern matching — longest phrase wins — and triggers
  the corresponding pre-recorded ASL video clip on the
  patient's screen.

Sample keyword mapping:

  Doctor says...                    Patient sees...
  ----------------------------      ----------------------------
  "Take your medicine"              take_medicine.mp4
  "Pain reliever once a day"        pain_reliever_daily.mp4
  "Unusual odor or discharge"       unusual_odor_discharge.mp4

SLIDE 9 — PROPOSED SOLUTION: THE PROTOTYPE
Template section: PROPOSED SOLUTION
----------------------------------------------------------------
Headline:
  SUMPAY — What We Built

Left column (what the prototype does):
  - 9-screen state machine managing patient and clinician flows
  - 4 background worker threads — fully thread-safe GUI
  - Trained on 4 ASL phrase classes, 120 samples total
  - 4 stochastic augmentations for handedness and tempo robustness
  - Fully offline: MediaPipe, PyTorch, Vosk, pyttsx3
  - Built with Python 3.11 + PyQt6
  - Degrades gracefully if any model file is missing

Right column (how we will validate it):
  - Recognition accuracy target: >= 80% before user testing
  - System Usability Scale (SUS) with:
      Deaf female participants  (target n >= 5)
      OB-GYN / GAD clinicians   (target n >= 3)
  - Target SUS score: >= 68 (above-average usability benchmark)

Bottom statement:
  The architecture is modular — adding a new phrase requires only
  30 new recorded samples and a single retraining run.
